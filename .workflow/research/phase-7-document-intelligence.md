## 2. Citable PDF-parsing / table-extraction approaches (§13–§14 engine input)

### 2a. Rule-based citable trio: Camelot / Tabula / pdfplumber / PyMuPDF

- **Camelot (MIT, Python): `read_pdf` → TableList → per-table pandas DataFrame; exports CSV/JSON/Excel/HTML/SQLite(+Markdown in fork); per-table `parsing_report {accuracy, whitespace, order, page}` for discarding bad tables without manual review; two modes Lattice (ruled tables) vs Stream (whitespace tables); text-based PDFs only, not scanned:** https://github.com/atlanhq/camelot (fetched 2026-10-11).
- **Camelot's stated design edge (citable as requirement rationale): control via tweakable settings + discard-by-metrics + DataFrame-native ETL output, vs tools that "either give a nice output or fail miserably":** https://dzone.com/articles/announcing-camelot-a-python-library-to-extract-tab (fetched 2026-10-11).
- **Tabula-java (MIT) is the engine behind Tabula; CLI flags `-l/--lattice` (ruling lines, spreadsheet-style) vs `-t/--stream` (no ruling lines), `-a area`, `-p pages`, `-f CSV/TSV/JSON`; tabula-py wraps it to pandas DataFrame via `read_pdf(path, pages="all", lattice/stream/guess/area>`:** https://github.com/tabulapdf/tabula-java/blob/master/README.md and https://tabula-py.readthedocs.io/en/latest/tabula.html (both fetched 2026-10-11).
- **Tabula method semantics (citable for §14 spec): `lattice` = force spreadsheet-style extraction when ruling lines separate cells; `stream` = force extraction when no ruling lines; `guess` = auto-detect table regions per page (independent of lattice/stream since tabula-java 1.0.3); `area=(top,left,bottom,right)` pins a page region:** same tabula-py docs URL (fetched 2026-10-11).
- **pdfplumber (MIT, pdfminer-based) vs PyMuPDF (AGPL-3.0 or paid commercial, MuPDF-based) benchmark on 1,422 real pages (July 2026): plain-text speed 180 pp/sec PyMuPDF vs 18 pp/sec pdfplumber (~10×); text+boxes 95 vs 22; table extraction 45 vs 8 pp/sec; TEDS table accuracy 0.847 pdfplumber vs 0.692 PyMuPDF; memory/100pp 45MB vs 180MB; pdfplumber best on bordered tables, struggles merged cells; PyMuPDF loses ~30% cell relationships on complex tables:** https://pdfmux.com/blog/pymupdf-vs-pdfplumber (fetched 2026-10-11).
- **License steer (product-relevant): PyMuPDF speed comes with AGPL copyleft → paid license or open-source obligation for commercial use; pdfplumber is MIT with no built-in OCR; neither does fast text + good tables + permissive license alone:** same URL (fetched 2026-10-11).

### 2b. Neural / layout-aware generation (citable upgrade path, not v1 default)

- **Docling (IBM Research Zurich, MIT, LF AI & Data, v2.129.0 verified 2026-09-22): open-source document conversion + layout analysis engine; parses PDF/DOCX/PPTX/XLSX/HTML/EPUB/scans/audio into Markdown + lossless JSON (DoclingDocument schema with bounding boxes + reading order); layout + reading-order recovery + TableFormer v2 table-structure models; runs locally; OCR pluggable (EasyOCR/Tesseract/RapidOCR); GraniteDocling VLM pipeline option; MCP server + REST serve:** https://docling.org/, https://docling.org/doc, https://github.com/docling-project/docling (all fetched 2026-10-11).
- **Docling comparison table (citable): layout+reading-order Yes (vs Unstructured partial hi_res, PyMuPDF/pdfplumber No); table structure via TableFormer; structured JSON = DoclingDocument; chunk-ready structure Yes; TEDS leader 0.887 (vs pdfplumber 0.847 in same benchmark):** https://docling.org/ and https://pdfmux.com/blog/pymupdf-vs-pdfplumber (both fetched 2026-10-11).
- **Docling provenance primitive (feeds §16): every element/chunk keeps page + bounding-box coordinates so a retrieved passage points at the exact page region for highlight, not just a page number; HybridChunker preserves header context + table matrix + page/bbox for RAG embedding:** https://docling.ai/use-cases/ and https://docling.ai/ (both fetched 2026-10-11).
- **Docling added XBRL parsing for financial reports (plus ODF, email, EPUB, Pages/Keynote, video/ASR keyframes):** https://github.com/docling-project/docling (fetched 2026-10-10). **EGX XBRL filings to feed it: `no data`** (carried over — EGX publishes PDFs).
- **Peer-reviewed benchmark context (2024 comparative study across Financial/Tender/Law/Scientific/Manual/Patent): Camelot highest Tender table score (0.72); Tabula led Manual/Scientific/Patent; PyMuPDF most consistent recall among rule-based; Table Transformer (TATR) high recall on Scientific/Financial/Tender (>0.9 Scientific) but not better than PyMuPDF/Camelot on Manual/Tender respectively:** https://arxiv.org/pdf/2410.09871v1 (fetched 2026-10-11).
- **2026 heterogeneous-science benchmark: heuristic libs (PyMuPDF/Camelot/pdfplumber) compete with vision/VLM approaches on some layouts at far lower compute; Docling/MonkeyOCR/Mathpix share best detection F1; GitHub popularity (June 2026) pdfplumber ~10.4k / PyMuPDF ~9.9k / Camelot ~3.7k stars:** https://arxiv.org/html/2511.16134v2 (fetched 2026-10-11).
- **Scanned-PDF caveat (citable): Camelot works with text-based PDFs only ("if you can click-and-drag to select text, it is text-based"); Tabula same constraint:** https://github.com/atlanhq/camelot (fetched 2026-10-11). **What share of EGX bulletin PDFs are scanned vs digital: `no data`** — not measured in this pass; pipeline must detect + route to OCR.

### 2c. Filing-specific gotchas: EAS vs IFRS deltas (REUSED + one fresh corroboration)

- **Egypt has not adopted IFRS; applies EAS (IFRS-based but not identical/comprehensive; 2015 base, 2019 IFRS 9/15/16 alignment, 2023 IFRS-17-like insurance effective FY from 1 July 2024; unaddressed items fall back to IFRS guidance):** REUSED Phase-3 §7 https://www.ifrs.org/content/dam/ifrs/publications/jurisdictions/pdf-profiles/egypt-ifrs-profile.pdf (fetched 2026-10-10).
- **Two major deltas: (1) employees' profit-sharing = equity distribution not P&L expense; (2) bespoke FX-translation model for 2016 + 2022 devaluations (extended to end-2023, one-time application with depreciation consequences on remeasured assets):** same URL (fetched 2026-10-10).
- **Disallowed options: PPE/intangibles/investment-property revaluation disallowed until Jan 2023; no single-statement comprehensive-income option (separate P&L required); no equity method in separate statements:** same URL (fetched 2026-10-10).
- **Fresh corroboration (DOES NOT replace the IFRS profile as primary): IFAC Egypt member profile confirms Not Adopted; EAS via ministerial decrees; Decision 69/2019 introduced IFRS-9/15/16-aligned standards + EAS 50 (IFRS-17-based); listed companies neither required nor permitted to use IFRS in consolidated statements:** https://www.ifac.org/about-ifac/membership/profile/egypt (fetched 2026-10-11).
- **UNCTAD Egypt case study corroborates the profit-sharing departure (EAS 1 vs IAS 1; knock-on EAS 22 EPS + EAS 38 Employee benefits) and lists the EAS↔IAS correspondence table (EAS 1→IAS 1 … EAS 39→IFRS 2):** https://unctad.org/system/files/official-document/c2isard45_en.pdf (fetched 2026-10-11).
- **§14 gotcha list (each row cited above): profit-sharing line sits in distributions not staff cost (mangles net-margin/EBITDA vs IFRS peers); FX-devaluation remeasurement distorts PPE + depreciation trends across 2016/2022–2023; pre-2023 revaluation reserves absent (P/B not comparable to IFRS revaluers); two-statement format mandatory (parser must expect separate P&L + OCI pages); separate-statement investments lack equity-method pickup. Parser + comparator must tag `accounting_basis=EAS` per filing and never silently pool EAS with IFRS peer ratios.**
